# Security Policy

## Supported Versions

This project does not currently maintain formal versioned release lines. Security support applies to the latest maintained code on `main` and the currently deployed production version.

## Reporting a Vulnerability

**Do not report security vulnerabilities through public GitHub Issues.**

To report a vulnerability, please use one of the following methods (in order of preference):

1. **GitHub Private Vulnerability Reporting** — submit a report through the [Security tab](https://github.com/GakutsuLabs/gakutsu.net/security/advisories/new) of this repository.
2. **Email** — send a report to gakutsu.community@gmail.com.

### What to Include

When reporting a vulnerability, please provide:

- Affected component or file path
- Steps to reproduce the issue
- Potential impact
- Proof of concept (where safe to share)
- Suggested remediation, if known

Please do not include production credentials, unnecessary personal data, or unrelated confidential information in your report.

## Response Expectations

Maintainers aim to acknowledge reports within **7 calendar days**.

After triage, maintainers may provide reasonable status updates. We do not guarantee a fix within a specific number of days — remediation timelines depend on severity, complexity, and maintainer availability.

## Coordinated Disclosure

Public disclosure should be coordinated after a fix is available or according to another timeline mutually agreed with the reporter.

## Good-Faith Research

We ask that security researchers:

- Avoid privacy violations
- Avoid data destruction
- Avoid service disruption
- Avoid social engineering
- Do not access data belonging to other users beyond what is strictly necessary to demonstrate the issue
